# Running MUT testcases

From the repository root, run one `.svh` testcase with one command:

```powershell
./sim/run_testcase.ps1 ./sim/mut/three_neurons_1D/testcases/tc_001_reset_access.svh
```

Run every `tc_*.svh` testcase for one MUT with:

```powershell
./sim/run_mut_regression.ps1 three_neurons_1D
```

The regression continues after a failure, reports the passed and failed counts,
and exits with a nonzero code if any testcase fails. The three-neuron regression
includes the full 190,000-step `tc_010_c_reference_trace` run.

Available cases:

| MUT | Testcase | Purpose |
| --- | --- | --- |
| `three_neurons_1D` | `tc_001_reset_access` | Reset values, CURRENT bit and byte writes, read-only registers |
| `three_neurons_1D` | `tc_002_axil_integration` | AXI and network integration |
| `three_neurons_1D` | `tc_003_commands` | START pulse, ignored writes, and status |
| `three_neurons_1D` | `tc_004_hardware_updates` | Step count, voltage snapshots, and reset |
| `three_neurons_1D` | `tc_005_timing` | Startup spacing, neuron and synapse completion, and measured clocks per step |
| `three_neurons_1D` | `tc_010_c_reference_trace` | Three-neuron RTL against C |
| `three_neurons_1D` | `tc_011_golden_reference_trace` | Fresh RTL against the recorded MATLAB golden trace, with C equality checks, accuracy metrics and plots |
| `single_neuron` | `tc_001_c_reference_trace` | Single-neuron RTL against C |
| `compute_current_vector` | `tc_001_consecutive_requests` | Ready-paced requests, neuron IDs, bit-exact vectors, input capture and reset |
| `base_two_exp` | `tc_001_basic_exponents` | Cubic exponential pipeline stimuli |

Each MUT has one `tb_<mut>.sv` testbench. Each `tc_*.svh` file defines a named task
selected by the runner. The runner compiles the sources and invokes XSim with
the testcase name. C comparison testcases call their Python helper from inside
the `.svh` task before and after the HDL activity. The runner compiles the C
reference executables before XSim because GCC cannot complete when launched
from XSim's `$system` process in this setup. Results stay under
`build/sim/<mut>/<testcase>/`.

AXI-Lite testbenches can include `sim/common/axi_lite_manager.svh` for read and
write transactions, then `sim/common/axi_lite_register_methods.svh` for register
checks. The common runner adds `sim/common/` to every MUT's include path.

## Shared current-vector engine

`compute_current_vector` uses `ready`, `id_in` and `id_out`. Wait for `ready`
while `valid_in` is low, then pulse `valid_in` for one clock. IDs 0, 1 and 2
identify the three neurons. Capture each vector when `valid_out` is asserted.
There is no request FIFO. The historical `tc_001_consecutive_requests` name is
retained, but the test now submits requests as soon as the engine is ready.
It checks 99 vectors, output IDs, captured inputs and reset recovery against
the retained scalar reference.

The single-neuron C test explicitly selects ID 0 and indexes state storage as
`neuron_state_variables[state_index][neuron_index]`.

The network C test uses the shared wrapper and per-neuron triangle arrays.
Startup is checked separately, then a trace row is captured on each
`step_valid` pulse. Every synapse pass must return each source ID exactly once.
A 512-clock progress timeout catches stalled startup or neuron processing.
External current for step 0 is supplied before startup. Current for the next
step is supplied after startup or the previous completed step because each
synapse pass prepares the neuron inputs for the following update.

Run a short network comparison with pulse transitions:

```powershell
./sim/run_testcase.ps1 three_neurons_1D tc_010_c_reference_trace -PlusArgs 'steps=12','pulse_start=2','pulse_end=7'
```

Without overrides the full 190,000-step reference trace remains the default.

The C reference tests use `EfficientAnalogNeuron-SNNsims/C_fixedpoint_modified`.
The network wrapper includes the modified three-neuron model, and the single-neuron
wrapper uses its shared integer exponential lookup. TC10 reads startup currents
from `startup_currents.txt`, generated by the C model, instead of assuming the old
linear approximation's startup value.

The modified C model calculates constant synapse coefficients with the original
`pow()` expression, matching the RTL parameter package. Runtime exponentials use
the matching lookup table in C and RTL. Both startup currents are 1050 Q8.

All C comparisons remain bit exact.

## MATLAB golden-reference testcase

Run the complete comparison from the IP repository root:

```powershell
./sim/run_testcase.ps1 three_neurons_1D tc_011_golden_reference_trace
```

The `.svh` path form also works:

```powershell
./sim/run_testcase.ps1 ./sim/mut/three_neurons_1D/testcases/tc_011_golden_reference_trace.svh
```

The runner checks that the recorded MATLAB trace is readable before compiling.
The testcase reuses TC10 to generate fresh C and RTL traces and check all 18
states bit for bit. After XSim exits successfully, the runner invokes
`scripts/compare_golden_reference.py` on the newly generated `hdl_trace.csv`,
using the same absolute Python interpreter that passed the initial check.
Plotting runs outside XSim so Vivado's Python environment cannot replace that
interpreter or hide its installed NumPy and Matplotlib packages.

All outputs for this run are written under
`build/sim/three_neurons_1D/tc_011_golden_reference_trace/`: `c_trace.csv`,
`hdl_trace.csv`, `vmem_overlay.png`, `vmem_error.png`, `state_metrics.csv`,
`spike_metrics.csv`, `spike_matches.csv` and `comparison_summary.json`.
The plot legend labels the generated result as IP RTL. The JSON records hashes
of the exact golden and RTL traces used.

The golden input is the saved 190000-step trace at
`../../EfficientAnalogNeuron-SNNsims/MATLAB/Golden_reference/results/golden_reference_trace.csv`
relative to the IP repository root. MATLAB is not rerun by this testcase.
The default stimulus is 80 pA on neuron 0 for steps 60000 through 140000,
inclusive. A shorter run compares the matching prefix of the saved golden trace:

```powershell
./sim/run_testcase.ps1 three_neurons_1D tc_011_golden_reference_trace -PlusArgs 'steps=70000'
```

This compares the first 70 ms. The pulse still begins at step 60000, so runs
ending before that point contain no input-driven spikes. Keep the pulse settings
unchanged when reusing this golden trace. Changed input currents or a run longer
than the saved reference are rejected. The JSON records the full golden length
and whether only a prefix was compared; all metrics and plots cover that prefix.

PASS means the C/RTL equality checks passed and the golden-reference analysis
completed with matching steps and inputs. It does not require the fixed-point
waveforms to equal the mathematical reference, and it does not assert an accuracy
acceptance limit. Voltage error and spike timing are reported for assessment.
The default spike matching window is 0.5 ms; ordinal diagnostics also expose
drift beyond that window when the total spike counts agree.

XSim's `PASS: tc_011_golden_reference_trace` message confirms trace generation
and C/RTL equality. The subsequent `PASS: golden-reference comparison` message
from the runner confirms the MATLAB comparison and plot generation. A failure
in either stage makes the runner fail.

This testcase requires Python 3.11 or later, NumPy, Matplotlib and GCC, in
addition to the existing Vivado simulation tools. The MUT regression discovers
TC11 automatically and therefore also runs this full golden-reference analysis.

`tc_005_timing` reports sample counts and minimum, mean and maximum cycles,
plus mean nanoseconds using the measured testbench clock period, over 128 updates.
Neuron latency runs from request acceptance to `single_neuron_valid_out`.
Network update latency runs from the first neuron request of an update to
`step_valid`; update interval measures successive `step_valid` pulses.
Startup timings run from sampling `ctrl_start` to the first `step_valid` and
to `startup_complete`, respectively.
